# TalentPulse AI

Employee attrition prediction and a GenAI HR helpdesk for IT companies. Codegnan hackathon, Team 13 "GenAI Guardians", problem GG-13 (Human Resources).

Full-stack app: **React + Vite** UI (Neobrutalism design), **FastAPI** backend, **SQLite** (Postgres/MySQL-ready via `DATABASE_URL`), **scikit-learn** models, and an LLM (Gemini, Groq or OpenAI) with an offline fallback.

![architecture](MAnaging%20Portal/docs/ARCHITECTURE.svg)

## Run it
```powershell
pip install fastapi uvicorn sqlalchemy pydantic pydantic-settings pyjwt bcrypt scikit-learn pandas numpy joblib pypdf python-multipart
python "MAnaging Portal\run.py"          # or double-click run.bat, optional port: run.bat 5060
```
Open http://localhost:5000/ui . API docs (Swagger): http://localhost:5000/docs . The built UI is already in `backend/static`, no Node needed to run.

Optional, for live GenAI: copy `MAnaging Portal/backend/.env.example` to `.env` and set `GEMINI_API_KEY` (or `GROQ_API_KEY` / `OPENAI_API_KEY` with `LLM_PROVIDER`). Without a key everything still works and the UI badges the output as "Offline".

## Requirements coverage
| Requirement | Where |
|---|---|
| Secure login, role-based access (4 roles + Super Admin) | JWT + `RoleChecker` on every route; routes hidden per role in the UI |
| Employee profiles, department and manager hierarchy | Directory, Org chart and Departments tabs |
| Leave application and approval | Leave page: balances, validation, overlap check, approve/reject with reason, notifications |
| Performance review cycles, ratings, comments | Reviews page (draft → publish) |
| HR policy document library | Policies page: paste text or upload PDF, read, delete |
| Engagement surveys | Surveys page: create/close (HR), answer anonymously (everyone), results + themes |
| Onboarding checklist | Profile modal in Directory; default checklist created for every new hire |
| **AI 1** attrition risk | Attrition radar: band, probability, top 3 reasons, suggested actions |
| **AI 2** performance trend flags | Performance flags page |
| **GenAI 1** policy helpdesk (RAG) | Helpdesk page: TF-IDF retrieval, grounded answer, cited sources |
| **GenAI 2** review drafter | Reviews page: bullets → 4-part draft, human edits and publishes |
| Admin dashboard | Org metrics + Home |
| Attrition visible only to HR and the employee's manager | Enforced in `check_attrition_access` and the team/dashboard routes |
| Synthetic data only | Seeded users/policies and a synthetic training set |
| Bonus: survey sentiment, exit interviews, chat-style notifications | Surveys (lexicon sentiment + AI themes), Attrition → Exit interview AI, notification bell |

## Honest notes about the AI
* The training set `data/ibm_hr_attrition.csv` is **synthetic**, generated by a formula that is shaped like the public IBM HR data. The model's score on it shows the pipeline works, not real-world accuracy. Retrain on the real Kaggle file with `python -m app.services.ai.train_attrition` if you have it.
* "Top 3 reasons" come from the model by resetting one input at a time to a healthy value and measuring how much the predicted risk drops.
* A prediction is a prompt for a conversation, never a decision about a person.

## Tests
```powershell

python -m unittest discover -s tests -v
```
